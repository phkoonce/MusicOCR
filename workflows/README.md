# Workflows

Project-specific material for the generic `musicocr` package: the data and notes of one particular
project. Nothing in `musicocr/` imports from here, and a workflow holds no logic -- anything reusable
belongs in the package (the horn-quartet scripts became `musicocr collection`).

## Layout of a project

```
workflows/<project>/
    collection.toml     committed   the spec: books, how pieces are found, per-book options, and
                                    [overrides.N] for table-of-contents/heading lines the OCR got wrong
    summary.md          committed   the last full combine table
    cache/              git-ignored derived results; delete it to redo them
        ocr/<book>-<size>-<mtime>/p<page>-<dpi>.json   page OCR (slow; keyed to the scan file)
        pieces.json                                     the piece table `split` found + the piece PDFs
input/<project>/        git-ignored the per-piece PDFs `split` cut (spec `input_dir`)
batches/<project>.toml  git-ignored the batch spec `collection batch` writes
output/<project>/       git-ignored OMR results and `_combined/pNN` scores
```

Edit `collection.toml` (including overrides) by hand; everything under `cache/`, `input/`, `batches/` and
`output/` is regenerated by the `musicocr collection` steps.

| Directory | What it is |
|---|---|
| `gb/` | The four-book horn-quartet collection (88 pieces sharing pages, table of contents in the scan). |
| `paxman/` | The Paxman horn-quartet gig book (~88 numbered pieces, no table of contents in the scan: `headings = true` reads the "NN. Title" headings off the music pages; printed bar numbers). |

Generic helpers that apply to any score stay in `scripts/` (`batch_run.py`, `combine_scenes.py`,
`compare_marks.py`, `experiment.py`, `make_sample.py`, `setup.sh`). Batch progress documents are written to
the git-ignored `batches/` directory next to the specs.
